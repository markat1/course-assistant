## Interpretation
# - Guard rejects oversized requests with 400 before admission; no GPU work.
# - Exactly the 252 capacity 503s were classified leave_disabled (overflow off).
# - About half of all placements moved a shared prefix to the other worker
#   (random tie-break, no prefix affinity): strong case for prefix_then_load.
# - CAVEAT: the ledger remembers only the LAST worker per prefix. Once both workers
#   have served a prefix, both hold it in their radix cache (Grafana ~97 % hit rate),
#   so most counted hops land on a warm cache. 431,331 tokens is an upper bound on
#   recompute, not the actual amount. Planned fix: remember the SET of workers that
#   hold each prefix and count a hop only when the destination is not in the set.
# - "KV hop" INFO log lines did not appear in the gateway log (logging level for
#   gateway.execution.hops); the counters are the evidence.
